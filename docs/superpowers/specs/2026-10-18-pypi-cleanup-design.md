# PyPI 历史版本清理设计

日期：2026-10-18。状态：用户已批准保留策略与执行方式；具体接口与验证步骤待计划评审。

## 目标与范围

`ppt-master` 是面向最终用户的工具，文档中的默认调用不锁定历史版本。清理旧的 PyPI 发行包以控制存储增长，不删除 GitHub tags、源码或 GitHub Releases。

保留规则：保留版本号最大的 10 个非空发行版本，以及最近 30 天上传过文件的所有版本。两者取并集；当前 PyPI 元数据 `info.version` 指向的默认版本也不得删除。版本按 PEP 440 排序，不按字符串或上传时间排序。30 天边界包含等于截止时间的上传；同一版本以最新文件上传时间为准。没有文件的版本不作为清理对象，也不占用 10 个保留名额。

2026-10-18 的公开数据快照显示：129 个非空版本，共约 2.83 GiB；上述策略保留 10 个版本，预计释放约 2.49 GiB。这是研究快照，不是执行时的删除清单。

## 执行方式

1. 独立 GitHub Action 每月运行，也可手动触发，只读取 PyPI 公开 JSON，产出完整清单、容量汇总、JSON artifact 和 job summary。不自动删除，也不创建 Issue。
2. 本机维护入口复用同一保留规则，实时查询并展示具体待删除版本和预计释放容量。操作者明确确认后，再交给固定版本的 `pypi-cleanup` 执行网页登录和删除。
3. 密码与双因素验证码仅由本机终端交互输入；不写入文件、报告、GitHub Secrets 或命令行参数。不自行实现网页登录，不承诺支持 `pypi-cleanup` 未支持的认证方式。
4. 删除前重新查询，确保待删除版本仍符合保留规则；不得将新出现的候选版本静默加入已确认清单。删除后查询并核实结果，不能仅凭子进程退出码或 HTTP 重定向宣称成功。

## 安全边界

- 项目名固定为 `ppt-master`；没有任意项目删除入口。
- 报告路径无认证、无删除副作用；本机删除拒绝在 GitHub Actions 或无交互终端中运行。
- 未确认、登录失败、第二因素失败、新网络邮件验证、PyPI 数据异常时停止，不绕过验证。
- 候选清单为空时不登录、不启动删除工具。
- 向清理工具传递精确匹配已确认版本的正则，不使用覆盖全部版本的宽泛表达式。
- 成功报告须包含实际删除与保留核验；部分失败或无法确认结果时，明确列出未完成版本并以非零状态退出。禁止自动重试删除 POST。

## 实施边界

新增仓库维护脚本与独立只读 workflow，不向用户侧 skill CLI 增加命令，不改包依赖或版本，不改 `auto-tag.yml`、`publish-pypi.yml`、同步工作流或发布门禁。

测试只放在 `skills/ppt-master/scripts/tests/`，使用 `unittest` 与内存样例、模拟网络；真实在线验证仅调用公开查询，不包含删除。未来首次真实删除仍由操作者在本机确认，不能以模拟测试或只读 smoke 代替。

## 批准与交付门槛

用户已批准“最新 10 个版本 + 最近 30 天”及“月度只读 Action + 本机交互删除”。默认版本保护、接口名称、文件布局和依赖固定方式属于本设计的实施选择，需随计划一并评审。计划批准后才实现；实现通过本地验证与 PR checks 后，再由用户决定是否合并。首次实际删除不属于计划编写或代码实现阶段。
